# Employee authored demonstration catalog

All company records and credit policies are fictional. These procedures create local simulated queue entries after employee review. Public references establish plausible processes: [Microsoft invoice matching](https://learn.microsoft.com/en-us/dynamics365/finance/accounts-payable/accounts-payable-invoice-matching), [Azercell subscriber documentation](https://www.azercell.com/en/personal/support/number-purchase-and-operations/who-may-be-a-subscriber-of-azercell.html) and [Azercell complaint handling](https://www.azercell.com/en/personal/help/complaint-handling.html), checked on 9 October 2026 and summarized in `sources/`. [Azercell's UiPath announcement](https://www.azercell.com/en/about-us/press-releases/news/azercell-ve-uipath.html) describes existing RPA use and services. This product demonstrates employee authored, tested procedures and makes no claim of inefficiency at Azercell.

Build the Docker sandbox with `npm run sandbox:build`, configure Azure as described in the main README and start `npm run dev`. The catalog is authored through the actual Create workflow conversation. Describe a procedure from `catalogRecipes`, upload its development files, inspect the generated rules and scripts, refine it, run an assertion on that exact revision, then explicitly review and publish. Recipes are draft candidates and never silently seed published versions. The export preserves the package hash, authoring conversation and test report. `createCatalogModel()` substitutes a disclosed deterministic model only for browser/API acceptance; it still uses the real write tool and Docker interpreter.

Inputs are actual PDF, XLSX, DOCX, CSV and read-only SQLite files. The Python tasks apply finite Decimal checks, compare prices and total tolerances before rounding, query snapshots and generate real Office artifacts using the supplied correspondence template. Missing required records produce a specific clarification letter. No task script writes a queue or sends correspondence.

Generate fixtures with `python scripts/generate-workflow-fixtures.py` using the sandbox Python or a Python installation with python-docx, openpyxl, pypdf, ReportLab and Pillow. Structured truth is saved before rendering to `.agent-state/validation/workflows/`, outside every agent mount. The input index records hashes, language and layout without answers. There are **50 frozen inputs: 18 development and 32 held out**—20 invoices, six onboarding and six complaints. Demonstrations use only development inputs. Business truth remains independent of layout, language and scans. The valid scanned invoice is expected ready; the conservative text parser cannot extract it and requests clarification, which is honestly scored as a false-blocked case. Unextracted scan facts still count against extraction accuracy. If held-out evidence informs a fix, move that failure into development and generate fresh held-out inputs with a new seed.

Run `node --import tsx --test tests/workflow-business.test.ts` for development controls, including subcent prices/totals, non-finite numbers and missing snapshots. Run `node --import tsx scripts/evaluate-workflows.ts --keep-state` for the actual author/test/publish API, isolated Docker tasks, protected artifact endpoints, independent ExcelJS/Word OOXML inspection and authoritative SQLite queue verification. `.agent-state/validation/workflows/evaluation-report.json` records exact evaluated package hashes, date/method, development/held-out counts, false-ready/false-blocked cases, extraction/artifact correctness, queues, duplicate prevention, latency and task usage. `duplicatesPrevented` counts repeat submissions; `duplicateRecords` counts unwanted queue rows.

Run `node --import tsx scripts/evaluate-general-agent.ts` for all **32 live general-agent cases**, or `--limit=1` for an initial latency measurement. It uses the configured Azure deployment, the same files/policies/templates/four tools and independent evaluator, with no catalog executable engine or answer key mounted. A development sample must pass before publication and approval; if setup fails, all held-out cases are still graded as draft tests and approval remains unavailable. `.agent-state/validation/workflows/general-agent-report.json` saves progress, setup failures, exact task package hashes, model usage and retained state. Failed tasks and partial comparisons remain visible; an incomplete subset is never described as the full comparison. Deterministic catalog execution is not evidence of live model generation quality.

The 9 October 2026 run graded 49/50 catalog cases; its valid image-only invoice was falsely blocked for lack of extraction. Held-out structured fact accuracy was 96.96%. The separate live run completed all32 investigations. Grading distinguishes business readiness, source facts actually delivered in structured results, optional field-path formatting, artifact contents and output-record conventions. Evidence wrappers and equivalent finite decimal formats are accepted. XLSX comments caused two ExcelJS compatibility failures; independently readable OOXML cells are not labelled corrupted. A declared AZN 560.01 total can pass the policy tolerance while differing from the calculated-total queue convention; that is an output-record difference, not a false-ready decision. Regrade retained results with `node --import tsx scripts/regrade-workflow-evaluation.ts <report-path>`; this reads protected artifact hashes and frozen truth without model calls or approval mutations. Reports are replaced atomically.
